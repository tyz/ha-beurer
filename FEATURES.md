# Features

* [ ] **Hardware timer-end events (`0xEB` and `0xEC`)**: Intercept asynchronous notifications `0xEB` (`RESPONSE_LIGHT_TIMER_END`) and `0xEC` (`RESPONSE_MOONLIGHT_TIMER_END`) in `notification_handler` so Home Assistant immediately detects when the daylight or moodlight channel is turned off by its internal hardware timer.
* [ ] **Hardware countdown timer control**: Support configuring the device's built-in hardware countdown timer (1 to 120 minutes) via opcode `0x33` (`REQUEST_UPDATE_LIGHT_TIME`), starting/enabling the timer via opcode `0x38` (`REQUEST_UPDATE_LIGHT_TIMER_ENABLED`), and canceling/disabling the timer via opcode `0x36` (`REQUEST_UPDATE_LIGHT_TIMER_DISABLED`), exposed via Home Assistant entities (e.g. `number` / `timer`) or services.
* [ ] **Firmware version detection**: Query the standard Bluetooth GATT Device Information Service (`0000180A-0000-1000-8000-00805F9B34FB`) on connect and read the Software Revision characteristic (`00002A28-0000-1000-8000-00805F9B34FB`) to populate `sw_version` in Home Assistant `DeviceInfo`.
* [ ] **Protocol constants and channel refactoring**: Rename legacy `reply_version` in `beurer.py` to `channel` (`1` = daylight/white, `2` = moodlight/RGB, `255` = all off) and define formal protocol opcode and channel constants in `const.py` / `beurer.py` matching the BLE protocol specification.
